The integration checks start real local servers and FFmpeg, inspect and decode
outputs, compare the requested source time with the result, test concurrent
idempotent requests, force a process interruption and inspect recovered jobs.

The retry proxy forwards an actual POST, consumes the server's complete 202
response and closes the downstream connection. Reusing the same key returns
the same job and one MP4 output. Using a fresh key for identical parameters
creates another job and output. The browser also reloads the page, restores
matching values and retries the saved request.

Additional UI checks verify that editing the form cannot discard an unresolved
key, storage errors release the form, a storage-clear error does not misreport
an accepted export, and a mismatched 2xx acknowledgment keeps the recovery key.
All owned test servers, proxy connections and headless browsers were stopped.

The source is an authored procedural pendulum clip with synthesized audio.
The demo uses one local worker and SQLite. Interrupted processing may run again
under the same job ID; the request contract does not guarantee exactly-once
worker execution.

Detailed runtime reports are written to ignored evidence directories.
The committed PNG captures show the current interface and retained-request
recovery control. Runtime databases and generated exports stay local.

Power loss, disk failure, hostile-media sandboxing, Safari/Firefox, mobile
hardware and production scaling were not verified. Use trusted test inputs
and a short DATA_DIR or TEST_DATA_ROOT on Windows. See README.md.
